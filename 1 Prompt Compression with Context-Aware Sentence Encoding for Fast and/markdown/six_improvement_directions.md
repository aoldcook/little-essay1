# 大模型文本信息提取压缩：6 个重点改进方向

这份文档整理了当前工作中最值得优先推进的 6 个改进方向，目标是在**尽可能保留原有语义**的前提下，进一步提升压缩效率、降低 token 开销，并形成更有论文价值的方法设计。

---

## 方向 1：把 `find_target_ratio` 从启发式函数升级成“可学习的预算分配器”

当前的 `find_target_ratio` 已经比简单 elbow 更合理，但本质上仍然是手工规则。更进一步的做法是：直接学习“这道题需要保留多少比例”。

### 核心思想

定义一个预算预测器：

\[
g_\phi(x) \rightarrow \hat r \in (0,1]
\]

其中：

- \(x\)：当前样本的特征
- \(\hat r\)：建议保留比例
- 目标：在尽量不损失答案质量的前提下，让 \(\hat r\) 尽可能小

### 可用特征

- 相似度分布熵
- top-1 与 top-2 差值
- top-k 相似度累计占比
- 高相关句比例
- 问题长度
- 实体数量
- 是否是多跳、比较、因果类问题

### 优势

- 解决“为什么这个压缩率合理”的问题
- 比手工函数更灵活
- 更容易形成论文中的方法创新点

---

## 方向 2：不要只做“独立句排序”，要做“集合选择”

当前方法是给每个句子独立打分，再取 top 句。这种方式简单有效，但会忽略以下问题：

- **覆盖度**：是否覆盖了问题涉及的多个子点
- **冗余度**：是否选了大量语义相近的句子
- **依赖链**：某句虽然分数不高，但可能是推理链中的桥接句

### 建议目标函数

\[
\text{Score}(S)=\sum_{s_i\in S}\text{Rel}(q,s_i)
+\lambda \,\text{Cover}(S,q)
-\mu \,\text{Redundancy}(S)
+\gamma \,\text{Bridge}(S)
\]

其中：

- `Rel`：问题与句子的相关性
- `Cover`：是否覆盖多个问题子点
- `Redundancy`：句子之间的冗余惩罚
- `Bridge`：桥接句或依赖句的奖励

### 可实现方式

- MMR（最大边际相关）
- 子模优化
- 基于实体链的选择机制

### 优势

- 适合多跳问答、因果推理、科研文本
- 选句质量通常优于“纯相似度 top-k”

---

## 方向 3：做成“两级压缩”：先选句，再做句内裁剪

纯抽取式压缩通常比纯 token pruning 更稳，但还可以进一步提升压缩率：

### 两级流程

1. **句子级筛选**  
   先保住语义骨架

2. **句内片段裁剪**  
   再删除句内不必要部分，例如：
   - 插入语
   - 括号补充
   - 举例说明
   - 修饰性从句
   - 与答案无关的背景信息

### 方法升级

从：

> select sentence

升级成：

> select sentence → keep answer-bearing span

### 优势

- 在保持句子级语义安全性的前提下进一步降 token
- 很适合作为论文中的独立创新点
- 有利于说明“句子级负责语义完整性，片段级负责高压缩率”

---

## 方向 4：不要默认“恢复原文顺序”就是最优，要研究“位置感知重排”

当前做法通常是筛选句子后，按原文顺序恢复。这有利于可读性，但未必总是最有利于大模型回答。

### 为什么值得研究

长上下文场景中，大模型往往存在明显的位置偏置：

- 对开头更敏感
- 对结尾也较敏感
- 中间内容容易被忽略

因此，压缩后信息的**摆放顺序**可能会影响最终回答效果。

### 可比较的 3 种策略

1. 原文顺序恢复
2. 纯相关度顺序
3. **位置感知重排**

### 一个可行方案：evidence sandwich

- 开头：最关键的直接证据
- 中间：桥接证据、解释链
- 结尾：边界条件、补充信息

### 优势

- 从“删什么”扩展到“删完后怎么摆”
- 更贴近 LLM 的注意力分布特性
- 很适合做 ablation study

---

## 方向 5：把单一问题编码改成“多视角任务表示”

当前方法通常只用一个 query embedding 去匹配句子。这在简单问答下效果不错，但在复杂问题上可能不够。

### 问题

单一 query 向量容易把“表面相关”误当成“真正有用”。

### 改进思路

把问题扩展成多个视角：

- 原始问题 \(q\)
- 预期答案类型 \(t\)
- 关键实体对 \(e\)
- 推理需求 \(r\)

然后综合多个相似度：

\[
\text{Rel}(s)=
\alpha \,\text{sim}(q,s)+
\beta \,\text{sim}(t,s)+
\gamma \,\text{sim}(e,s)+
\delta \,\text{sim}(r,s)
\]

### 举例

一个问题可能同时包含：

- “是什么”：定义型
- “为什么”：因果型
- “A 和 B 的区别”：比较型

不同类型会影响应该保留的上下文范围。

### 优势

- 从“query-aware”升级到“task-aware”
- 对复杂问题更稳
- 更适合论文中强调任务适应性

---

## 方向 6：让压缩器对“目标大模型”负责，而不只是对 embedding 相似度负责

当前系统优化的通常是：

> 被选中的句子和问题 embedding 更接近

但真正想优化的是：

> 压缩后，目标 LLM 的答案尽量不变，同时 token 尽量少

这两者并不完全等价。

### 更合理的训练目标

\[
\mathcal L
=
\mathcal L_{\text{rank}}
+\lambda_1 \mathcal L_{\text{answer-preserve}}
+\lambda_2 \mathcal L_{\text{budget}}
\]

其中：

- \(\mathcal L_{\text{rank}}\)：句子相关性排序损失
- \(\mathcal L_{\text{answer-preserve}}\)：压缩前后答案一致性损失
- \(\mathcal L_{\text{budget}}\)：压缩率约束

### 一个务实做法

- 用完整上下文生成 teacher answer / teacher logits
- 用压缩上下文生成 student answer / student logits
- 最小化两者之间的差异（如 KL、语义相似度损失）

### 优势

- 压缩器直接对最终任务负责
- 更贴近真实使用目标
- 能把“回答质量保持”纳入训练环节

---

# 优先级建议

如果当前只打算先推进两个方向，建议优先做：

## 第一优先：学习化预算预测

原因：

- 与现有代码兼容性最高
- 最容易快速落地
- 很容易在论文中形成清晰的方法贡献

## 第二优先：集合选择 + 重排策略

原因：

- 直接提升选句质量
- 同时覆盖“选得更准”和“摆得更好”
- 很适合作为实验对比和消融分析内容

# 论文表述建议

这 6 个方向可以组织成一条比较完整的论文主线：

> **adaptive budget + set selection + two-stage compression + position-aware arrangement + task-aware relevance + target-model-aware optimization**

这样会比“单纯更换 embedding 模型”更像一个完整的方法论文。

---

# 总结

这 6 个重点方向分别从以下层面增强你的压缩系统：

1. **压多少**：学习化预算预测  
2. **选什么**：集合选择而非独立句排序  
3. **压到多细**：句子级 + 片段级两级压缩  
4. **怎么摆**：位置感知重排  
5. **看问题的方式**：多视角任务表示  
6. **真正优化什么目标**：面向目标大模型的答案保持训练

如果后续继续推进，最推荐先做“预算预测器”和“集合选择机制”，因为它们最容易形成稳定提升，也最容易直接整合到你当前已有代码框架中。
